# pi-side

This directory contains the Raspberry Pi–side analysis pipeline used in the 701Lab project.

The Pi-side analysis flow is organized as a lightweight, deterministic post-run pipeline that operates on the run-based data structure generated by the acquisition system.

At the current stage, the main components are:

- [a0_run_pipeline.py](./a0_run_pipeline.py)  
  The main Pi-side pipeline orchestrator.  
  It runs the A1–A5 steps in sequence for a target run and can optionally transfer verified results to the Windows-side `_incoming` area.

- [a1_make_qc_gate.py](./a1_make_qc_gate.py)  
  Generates run-level quality control reports (`qc_report.json` and `qc_report.md`).

- [a2_make_provenance_schema.py](./a2_make_provenance_schema.py)  
  Generates provenance and schema descriptions for the run (`provenance.json` and `schema.json`).

- [a3_make_segments.py](./a3_make_segments.py)  
  Generates sensor-validity segments such as GPS, audio, polar, and IMU intervals.

- [a4_make_events.py](./a4_make_events.py)  
  Normalizes events such as start, stop, restart, exception, and quality-related signals into `events.csv`.

- [a5_make_run_index.py](./a5_make_run_index.py)  
  Builds a simple run index across multiple runs for later selection and transfer.

The overall role of this area is to produce lightweight derived artifacts on the Raspberry Pi side before later processing, visualization, or archival handling on the Windows side.
